# Master Build Prompt — AI Lead-Operations SaaS
_Reverse-engineered from the irfanapp/irfaninvest production system, generalized for a multi-tenant SaaS product._

---

Build a production-grade, multi-tenant SaaS platform called **[PRODUCT_NAME]** — an AI-powered lead-operations and marketing-intelligence system for high-ticket sales businesses (original vertical: luxury real estate). The platform captures every lead a client's website generates, calls each lead with an AI voice agent within minutes, psychologically profiles every conversation, and unifies marketing analytics — so a small sales team closes like a large one.

## 1. Core Product Concept

One dashboard where a business owner sees: website traffic (GA4), ad spend and performance (Google Ads), every inbound lead (forms, AI chat, phone calls), every AI phone conversation with transcript and buyer-psychology profile, and AI-generated executive insights. Behind it, an automation layer that acts on leads without human intervention.

**The killer loop (must work end-to-end):**
1. Visitor clicks an ad → submits a form on the client's website (name, email, country code + phone, property/product interest, budget, timeline, UTM params).
2. Lead is stored in the database via an edge function (service-role key), mirrored to a Google Sheet, and appears in the dashboard.
3. Within 2 minutes, an automation watcher picks up the new lead and places an outbound AI voice call — respecting the lead's local timezone (derived from country code), a configurable calling window, deduplication (never call the same lead twice), max-attempt caps, and test-row exclusion.
4. The AI voice agent (warm, consultative persona; speaks the caller's language incl. RTL languages like Arabic/Persian) qualifies the lead conversationally: property type, location, budget, timeline, purpose. If interest is high, it books a video consultation into Google Calendar and sends a WhatsApp/SMS confirmation.
5. When the call ends, the voice platform posts an end-of-call report. The system then: updates the lead's status in the dashboard, appends a full call record to a "report-after-call" sheet (25 columns: person details + call metadata: duration, answered?, ended reason, recording URL, attempt #, appointment, cost), and appends a psychology row to a "call-conversation" sheet (20 columns).
6. The psychology analysis (17 structured fields, generated by the voice platform's analysis plan): still_interested, consultation_requested, preferred_time, budget, preferred_location, property_type, interest_level (hot/warm/cold), buyer_intent (high/medium/low), buyer_persona (investor vs end-user, decisiveness, risk appetite), sentiment, key_motivations (ROI/residency/lifestyle), objections, confidence_level, lead_score (0-100), qualified (bool), recommended_strategy, followup_message.

## 2. Tech Stack (proven in production)

- **Frontend/API:** Next.js (App Router, server-rendered; all DB access in API routes — zero DB keys in the browser), React, Tailwind, Recharts.
- **Database:** Supabase (Postgres + RLS + edge functions). Tables: `leads` (lead_id, dedup_key, contact fields, phone_country_code, property_interest, budget, lead_quality, lead_score, buyer_intent, call_status, call_attempt_count, last_called_at, next_call_at, vapi_call_id, voice_source, appointment fields, utm_*, raw_data jsonb), `call_attempts` (full call log), `analytics_ga4*`, `google_ads_campaign_data`, `campaign_unified` (view joining ads+ga4 with cost_per_lead).
- **Automation:** n8n (two workflow patterns): (a) a 30-minute sync pipeline — pull GA4 report, Google Ads campaigns, form-lead sheet, AI-chat-conversation sheet; normalize (combine Country Code + Phone into E.164, strip formula errors); AI-qualify text leads (LLM with structured output parser: lead_score, lead_quality, buyer_intent, next action, summary, suggested reply); POST everything to the dashboard's ingest webhooks. (b) a 2-minute auto-call watcher — read new sheet rows, history-dedupe on Lead ID, timezone/calling-window gate, max 5 calls per run, place the voice call with full lead metadata, log the attempt.
- **Voice:** Vapi (assistant + phone number imported from Twilio; server URL → end-of-call webhook; analysisPlan with summaryPlan + structuredDataPlan for the 17 psychology fields; assistantOverrides.variableValues to personalize each call; metadata to correlate call → lead). Twilio for PSTN + WhatsApp/SMS. Support the "local number → unconditional call-forward → platform number" pattern for countries where DIDs aren't purchasable (e.g., Oman).
- **AI:** Claude (voice agent persona, executive insights, CEO reports), plus a cheap model (e.g., GPT-4o-mini / Haiku) for high-volume lead qualification.
- **Deploy:** Vercel (server-side builds, env in project settings). Health probe at `/api/health` (public: status, db latency, config flags, version).

## 3. Dashboard (11 tabs, exactly as built)

KPI header: Page Views (30d), Users (28d), Events, GA4 Leads, Ads Clicks + CTR, Cost/Lead + spend.
Tabs: **Marketing** (traffic over time, engagement depth, top country/page, traffic distribution, day-of-week), **Top Pages**, **Geography**, **Google Ads** (per-campaign impressions/clicks/CTR/CPC/cost/conversions), **Form Leads** (searchable table with rich property fields), **AI Convos**, **Qualified AI** (score-filtered), **Combined**, **Calls** (call log table with expandable detail: transcript, quality, appointment, sales rep), **Voice** (live pipeline status pill, KPI cards — voice leads / inbound / outbound / booked / calls-24h — and conversation cards with AI summary + expandable transcript + psychology chips), **AI Insights** (one-click Claude analysis of all current data into an executive report).

## 4. API Surface (28 routes pattern)

- **Ingest webhooks (12), machine-auth via `x-webhook-secret` header:** ga4, ga4-realtime, ga4-campaigns, google-ads, form-leads (upsert on dedup_key: email-first, then last-8-phone-digits, then content hash; never create duplicates), leads, ai-conversations, ai-qualified-leads, voice-leads, call-attempts, update-lead (post-call status), call webhooks.
- **Calling queue:** `GET /api/leads/for-calling` — safety-filtered queue: E.164-normalized `e164_phone`, `since` param (only new leads), `max_attempts` cap, excluded statuses (booked/not_interested/do_not_call), cooldown via next_call_at, business-hours flag, test-row exclusion (`__*`, `zz*`, `*test*`, `*probe*`).
- **Data reads** (calls, leads, data, campaigns, conversations, realtime) — session-gated.
- **AI:** analyze (exec insights), score-leads, leads-ceo-report.
- **Auth:** POST/DELETE `/api/auth`. **Ops:** `/api/health`.

## 5. Security Model (implement from day one)

- Human auth: password → HMAC-SHA256 signed httpOnly cookie (30d), verified in Next.js middleware/proxy on EVERY page and data API; login page; sign-out. (SaaS: upgrade to Supabase Auth multi-user, keep the same gate architecture.)
- Machine auth: shared `x-webhook-secret` header for all automation traffic; webhooks individually verify it.
- Public surface strictly limited to: marketing landing `/`, `/login`, `/api/auth`, `/api/health`, `/api/webhook/*` (self-verifying).
- Supabase RLS ON: public-content tables = anon SELECT-only policies; sensitive tables (leads, calls, analytics) = no anon policies, server uses service-role key.
- Security headers (X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy). `.env.example` documenting every var. No secrets hardcoded in workflows.

## 7. SaaS-ification Layer (the productization work)

- **Multi-tenancy:** org_id on every table + RLS per org; per-tenant encrypted credential vault (GA4 property, Google Ads customer ID, Sheets, Twilio SID/token, Vapi key, calendar).
- **Onboarding wizard:** connect Google (OAuth for GA4/Ads/Sheets/Calendar) → connect/buy a phone number (Twilio subaccount or platform-provisioned) → paste website form webhook OR install a JS form-capture snippet → write the agent persona (template: company details, goals, qualification questions, conversation rules, language/culture notes, closing scripts) → set calling window + timezone rules → go live.
- **Per-tenant n8n:** template the two workflows and provision per org (or rebuild as internal queue workers: cron sync + call scheduler) — parameterized by tenant credentials.
- **Billing:** subscription + usage (voice minutes, AI analysis) via Stripe; show per-call cost (the stack yields ~$0.07-0.10/min all-in).
- **White-label:** tenant logo/colors/font on landing + dashboard; custom domain.
- **Compliance:** call-recording consent per jurisdiction, do_not_call enforcement, data export/delete.

## 8. Quality Bar (non-negotiables learned in production)

Every webhook idempotent (upsert on dedup_key). Every phone normalized to E.164 with country-code fallback rules. Sheet formula-error strings (`#ERROR!`) treated as null. Never call a lead twice (attempt counter + history dedupe + status exclusions). Brittle side-effects (sheet writes, WhatsApp) must not kill the pipeline (continue-on-error). End-of-call payload parsed from the voice platform's NATIVE format. A 16-point auth/integration test checklist runs before every release. Health probe public; everything else locked.
